# Desk Pro — Trae Master Prompt Pack

Date: 2026-03-06

## 1) Operating model

This pack is designed for a **Trae-first, SSH-backed, shared-centered** workflow:

- **Trae** generates or patches modules from prompts.
- **admin-trading** is the integration hub and Git source of truth.
- **/shared** is the delivery bus across Linux machines.
- **student** runs AI / probability / pattern workloads.
- **db-layer** stores timeseries, analytics, and signal history.
- **cursor-ai** is the prompt + review + deployment workstation.

Target system logic:

`Data Sources -> Collectors -> Scanner -> Derivatives Analytics -> Probability -> Decision/Risk -> Execution (optional) -> Database -> Desk Pro Dashboard`

## 1.1) Current State & Standards (2026-03-12)
See `docs/master_pack/00_current_state_and_standards.md` for the absolute truth.
Key points:
- **Canon Workflow**: `modules/workflow_post_change_v2` (no-sudo patch applied).
- **Deprecated**: `workflow_post_change_v2_fix3` (Merged), `fix1/fix2` (Obsolete/Kept).
- **Naming**: Prefer `scripts/cmd.sh` over `<module>_cmd.sh`.
- **Wrappers**: Always register in `registry/wrappers_registry.yaml`.

## 2) Golden rules for every Desk Pro module generated by Trae

Trae must follow these rules unless the prompt explicitly overrides them:

1. Keep modules **small, composable, and machine-aware**.
2. Respect the current multi-machine layout:
   - `admin-trading`: webhook, signal, scanner, orchestration, integrations
   - `student`: AI, probability, pattern/regime, heavy analysis
   - `db-layer`: storage, analytics, APIs, dashboard backend
   - `cursor-ai`: development, prompt orchestration, Git, packaging
3. Default repository root: `/opt/trading`
4. Shared exchange path available from Linux machines: `/shared`
5. Every module must ship with (inside `scripts/`):
   - `sanity_check.sh`
   - `cmd.sh` (Generic CLI wrapper)
   - `menu.sh` (Interactive menu if applicable)
   - install or upgrade script if relevant
   - minimal README
   - logs written both to terminal and file when applicable
6. Prefer **safe incremental patches** over large uncontrolled rewrites.
7. Never break existing working webhook/perf flows unless the prompt explicitly asks for a refactor.
8. Use configuration files or env vars rather than hardcoded secrets.
9. Produce output that is directly usable over SSH.
10. When possible, write reports, exports, or temporary artifacts under `/shared`.

## 10) SSH/shared deployment pattern after Trae output

Use this operating sequence after Trae generates a module:

1. Review output on `cursor-ai`
2. Save the generated pack under `/shared/inbox/<module_name>/` or apply directly in the repo on `admin-trading`
3. SSH into the target machine
4. Install/copy files into `/opt/trading`
5. Run module `sanity_check.sh`
6. Run `<module>_cmd.sh` quick test
7. If interactive flows exist, test `<module>_menu.sh`
8. Capture logs and useful artifacts under `/shared/reports/<module_name>/`
9. Journal the step
10. Commit and push if validated
