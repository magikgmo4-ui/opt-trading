# 00_INITIAL_PROJECT_DOC

## 1_MASTER_TARGET

Valider le plan documentaire recommandé par le builder OpenClaw lors du dry-run précédent, avant toute création de documentation opérationnelle réelle.

## 2_INITIAL_PROJECT_DOC

Ce document initialise le child GO de revue du plan documentaire builder. Il reste la référence figée du cadrage initial du chantier.

## 3_INITIAL_NEED

Le child précédent a confirmé que le builder peut produire une réponse structurée en dry-run pour une tâche documentaire. Il faut maintenant examiner cette proposition, décider quels documents sont réellement pertinents, et préparer un plan validé pour un prochain child d'écriture documentaire.

## 4_MASTER_PROJECT_PLAN

1. Relire les artefacts du child dry-run.
2. Extraire les fichiers recommandés par le builder.
3. Classer chaque document recommandé.
4. Identifier les risques et limites.
5. Produire une matrice de décision.
6. Définir le prochain GO d'écriture documentaire si le plan est validé.

## 6_FINAL_TARGET

Produire une revue documentaire approuvée, traçable et bornée, avec une décision claire pour chaque fichier recommandé.

## 12_INVARIANTS

- Aucun SSH.
- Aucun patch runtime.
- Aucun push avant closeout.
- Aucun appel builder obligatoire dans ce child.
- Aucune modification des index globaux.
- Aucune création des documents opérationnels finaux dans ce child.
- Ce child valide le plan, il ne l'exécute pas.
