# 00_INITIAL_PROJECT_DOC

## 1_MASTER_TARGET

Adopter localement le pack documentaire OpenClaw builder produit dans le child précédent, sans modifier les index globaux ni les surfaces runtime.

## 2_INITIAL_PROJECT_DOC

Ce document initialise le child GO d'adoption documentaire builder. Il reste la référence figée du cadrage initial du chantier.

## 3_INITIAL_NEED

Le child précédent a produit quatre documents builder validés : guide opérateur, vue architecture, workflow contrôlé et garde-fous sécurité. Il faut maintenant statuer sur leur adoption comme référence opératoire locale, définir leurs usages autorisés, et préparer un éventuel prochain GO d'intégration plus large si nécessaire.

## 4_MASTER_PROJECT_PLAN

1. Vérifier les artefacts du child d'écriture documentaire.
2. Définir le périmètre d'adoption.
3. Produire une matrice d'adoption.
4. Produire une décision d'adoption.
5. Fermer le child avec un verdict clair.
6. Reporter toute intégration globale à un GO séparé.

## 6_FINAL_TARGET

Obtenir une décision d'adoption documentaire claire, traçable et bornée pour le pack builder.

## 12_INVARIANTS

- Aucun SSH.
- Aucun patch runtime.
- Aucun fix gateway token.
- Aucune modification des index globaux.
- Aucun déplacement ou renommage des documents existants.
- Aucun changement dans `ACTIVE_STREAMS`, `GO_INDEX`, `NEXT_GO`, `REPRISE` ou `BRANCH_STATE`.
- Adoption locale uniquement dans le dossier du child.
- Toute intégration globale devra être un GO séparé.
