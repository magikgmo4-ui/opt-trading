TRAE_DRIVE_REFERENCE_PACK_V1 — PACK DE RÉFÉRENCE ET SYNCHRONISATION

## 1. OBJECTIF DU PACK
Définir la politique de conservation, de sécurisation et de synchronisation du socle doctrinal Trae. Ce document assure que la "Loi" (Doctrine) survit à la machine locale et reste accessible pour tout réamorçage d'environnement.

## 2. PÉRIMÈTRE DE CONSERVATION (SCOPE CANONIQUE)
Tout document listé dans le `TRAE_CANONICAL_INDEX` actif, ainsi que les packs opérationnels de support, doivent être conservés.
Liste minimale requise (basée sur Index V1.2) :
1. TRAE_CANONICAL_INDEX_V1.2
2. TRAE_DOCTRINE_CHAIN_V1.1
3. TRAE_STATUS_POLICY_V1.1
4. TRAE_MISSION_TEMPLATE_V1.1
5. TRAE_EXECUTION_REPORT_TEMPLATE_V1.1
6. TRAE_REVIEW_VERDICT_TEMPLATE_V1.1
7. TRAE_CLOSURE_TEMPLATE_V1.1
8. TRAE_SESSION_OPENING_PACK_V1.1
9. TRAE_DRIVE_REFERENCE_PACK_V1 (Ce document)
10. ETABLI_TRAE_SOCLE_CANONIQUE

## 3. BIBLIOTHÈQUE LOCALE (CACHE CHAUD)
- **Emplacement Canonique** : `C:\\Users\\ghost\\opt-trading\\docs\\ot\\trae\\docs\\ot\\trae\\trae_pack_texts\\\trae_pack`
- **Format** : Fichiers `.txt` bruts (UTF-8).
- **Rôle** : Source de vérité immédiate pour l'agent Trae et l'opérateur en cours de session.
- **Règle d'Or** : Aucun document doctrinal n’est opérationnellement disponible pour la session s’il n’existe pas physiquement dans cette bibliothèque locale canonique.

## 4. ARCHIVE EXTERNE (COLD STORAGE)
- **Emplacement** : Drive / Stockage Cloud (URL/Path à définir par l'Ops).
- **Rôle** : Sauvegarde immuable et source d'amorçage pour nouvelle machine.
- **Fréquence** : Mise à jour obligatoire à chaque modification de statut doctrinal (passage en CLOSE).

## 5. RÈGLE DE SYNCHRONISATION MINIMALE
1. **Sens Unique** : La modification se fait en Local lors d'un chantier doctrinal, puis est poussée vers l'Externe après validation (CLOSE).
2. **Atomicité** : Le pack doit être synchronisé comme un tout cohérent pour éviter les versions panachées (ex: Index V1.2 avec Mission V1.0).
3. **Vérification** : La présence du fichier local prime sur la mémoire de l'agent.

## 6. CAS D'USAGE
- **Cas A - Initialisation Machine** : Télécharger le Pack complet depuis l'Externe vers le dossier Local.
- **Cas B - Perte de Contexte** : L'agent a "oublié" les templates -> Relire le dossier Local.
- **Cas C - Audit** : Comparer le dossier Local avec l'Index Canonique pour détecter les manquants ou les altérations.

## 7. POINTS INDÉCIDABLES (À RÉGLER PAR OPS)
- L'URL ou le chemin exact du stockage externe n'est pas défini dans ce pack (dépend de l'infrastructure).
- La méthode de transfert (copie manuelle, script sync, git push) est laissée au choix de l'opérateur, tant que le résultat (fichier présent) est là.
