PRE_V1_REPO_LANDING_PLAN

Objet
- Fixer où chaque bloc pré-V1 doit atterrir dans le repo canonique.
- Éviter que le pack reste une doctrine parallèle hors repo.
- Préparer un merge propre, progressif et traçable.

Principe
- Canonique final = repo.
- Pack pré-V1 = support de revue, transport, reprise et gel.
- Toute pièce retenue comme vérité durable doit être matérialisée dans le repo.

Mises à jour repo à prévoir en parallèle
- docs/ot/trae/README.md
  - ajouter l’ordre de lecture des nouveaux fichiers V1
- docs/ot/README.md
  - ajouter un pointeur vers docs/ot/trae/
- docs/ot/kanban/opt_trading_kanban_source_of_truth.md
  - ajouter une référence au socle pré-V1 si retenu
- workflow ou index OT central
  - référencer la checklist multi-étapes comme modèle officiel pour missions longues

Arborescence shared à aligner
- Ajouter /shared/backups/
- Ajouter /shared/docs/export/
- Conserver repo comme vérité versionnée
- Conserver shared comme hors-repo opératoire

Ordre de merge recommandé
1. matérialiser 01 à 08 dans docs/ot/trae/
2. mettre à jour README / index / workflow
3. matérialiser 09 et 10
4. vérifier cohérence kanban / reprise / runtime docs
5. déclarer le socle gelé en PRE_V1_CLOSE ou V1_READY selon validation finale

Ce qui ne doit pas arriver
- ne pas laisser le pack comme unique source de vérité
- ne pas disperser les fichiers V1 dans plusieurs emplacements incohérents
- ne pas matérialiser les backups dans le repo
- ne pas mélanger export de doc et doc canonique

Verdict
- Le meilleur prochain mouvement n’est plus d’écrire un nouveau texte de fond.
- C’est de faire atterrir proprement le socle dans docs/ot/trae/ et d’aligner README / workflow / kanban autour de lui.
