# UI Screenshots — Gap Analysis

## Gap A — Pas de relation canonique screenshot ↔ analyse
Les captures existent, mais la liaison structurée avec une analyse lisible n’est pas encore normalisée.

## Gap B — Pas encore de séparation explicite Daily vs Archive
Le besoin métier est clair, mais la structure de conservation dédiée n’est pas encore formalisée.

## Gap C — La future lecture MSI n’existe pas encore
On sait que MSI doit héberger la surface de lecture, mais aucune UI dédiée n’est encore construite.

## Gap D — Trop de volume brut pour une simple lecture dossier
`desk/snapshots/` contient beaucoup de captures. Une future UI devra proposer :
- filtres
- résumés
- priorités
- statut d’archivage

## Gap E — Les flux de cleanup ne doivent pas être mélangés trop tôt à ce chantier
On prépare d’abord la logique UI/registre d’archive, puis ensuite seulement l’intégration avec la rétention.
