CONTEXTE
Un opérateur doit transférer un sous-ensemble d’artefacts du repo (docs + rapports OT) vers une autre machine via la surface canonique shared.
On veut un bundle ZIP strict (liste explicite, pas d’excès), destiné à une livraison ciblée.

CLASSE
BUNDLE TRANSFER — livraison documentaire

OBJECTIF
Préparer un bundle ZIP contenant uniquement les artefacts nécessaires pour partager l’état “starter pack” (docs + kanban + livrables OT associés), sans inclure de code runtime.

CONTRAINTES
- Ne pas inclure de secrets, clés, ou fichiers volumineux non nécessaires.
- Ne pas inclure de runtime machine (`scripts/*`) ni de données (`data/*`) sauf preuve.
- Lister explicitement chaque fichier à inclure (pas de glob large).
- Le bundle est une livraison documentaire : privilégier les fichiers Markdown/TXT.

DEPENDANCES
- Risque : inclure des fichiers hors périmètre par erreur.
- Dépendance : vérifier l’existence réelle de chaque fichier listé avant création du ZIP.

LIVRABLE
- docs/master_pack/00_current_state_and_standards.md
- docs/master_pack/mission_starter_pack/00_mission_start_guide.md
- docs/master_pack/mission_starter_pack/01_mission_template.md
- docs/master_pack/mission_starter_pack/02_validation_checklist.md
- workflow_ai/WORKFLOW.md

- OT_STARTERPACK_AUDIT_01_CLOSING.txt

- OT_STARTERPACK_PATCH_01_CLOSING.txt

- OT_STARTERPACK_PATCH_02_CLOSING.txt
- OT_STARTERPACK_ADOPTION_01_REPORT.md
- OT_STARTERPACK_ADOPTION_01_CLOSING.txt

VALIDATION
- Vérifier que le ZIP ne contient que les fichiers listés.
- Vérifier que les fichiers sont lisibles (UTF-8) et non vides.

SUITE
Déposer le ZIP dans `/shared/_bundles/` avec un nom horodaté et documenter la livraison.
