CONTEXTE
Le repo opt-trading utilise 2 registres YAML comme sources de vérité :
- registry/modules_registry.yaml
- registry/wrappers_registry.yaml

Le patch concerne uniquement l’alignement du “registry central” (ajout/modif d’entrées), sans refactor global ni changement runtime machine.

CLASSE
PATCH LOCAL — registry central

OBJECTIF
Mettre à jour de façon cohérente les entrées module/wrappers du registry central pour refléter l’état réel du repo, sans casser les conventions (wrappers_expected, audience, status).

CONTRAINTES
- Ne pas modifier le code runtime (scripts/*) hors besoin documentaire explicite.
- Ne pas inventer des wrappers ou modules non présents dans le repo.
- Conserver les conventions de champs existantes dans les YAML.
- Produire une clôture : doc canonique touchée + kanban + point de reprise alignés.

DEPENDANCES
- Risque : incohérence modules_registry.yaml vs wrappers_registry.yaml.
- Dépendance : vérifier les chemins target_script existants dans les modules.

LIVRABLE
- registry/modules_registry.yaml (entrées module)
- registry/wrappers_registry.yaml (entrées wrappers)
- OT_*_REPORT.md (preuve/justification du changement)
- OT_*_CLOSING.txt (clôture + reprise)

VALIDATION
- Vérifier que les YAML restent lisibles et cohérents (pas de champs manquants, indent stable).
- Vérifier que chaque wrapper référencé pointe vers un fichier existant.
- Vérifier que chaque module référencé existe sous modules/<name>/.

SUITE
Ajouter un sanity check simple (optionnel) qui détecte les entrées orphelines module/wrapper.
